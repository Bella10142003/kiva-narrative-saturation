## ▶️ 一行命令跑通模拟验证（约 90 秒）

原始数据不能再分发，所以仓库里带的是**动真实数据之前**用来自我证伪的那套模拟工具：
生成 2 万条埋了真实系数的合成贷款 → 跑完整分析流水线 → 拿从不许读的答案本逐项对分。

```bash
git clone https://github.com/Bella10142003/kiva-narrative-saturation.git
cd kiva-narrative-saturation
pip install numpy pandas scipy scikit-learn
bash run_demo.sh
```

不需要竞赛数据，不需要任何凭证，输出落在 `6_模拟验证/_run/`。

它当时查出来的结果并不好看：提案的主规格把市场拥挤度 **高估了约 3 倍**（C 估计 0.444，真值 0.138），
作弊对照证明偏误来自那个分析端看不见的行业-周冲击；而只用上架时点构造、不可能被结果污染的**镜像池**
把估计拉回 0.107。代价是同质度被衰减（H 从 0.170 掉到 0.054）——这是一笔明说的交易：**用系数衰减换掉内生性偏误**。
14 个方法论环节照此逐个打分：**3 个真有用、4 个恒为空转、5 个写法会误导、2 个反而更差**，
砍掉之后分析工作量少了约一半，能站住的结论一个没少。逐条判定见 [6_模拟验证/模拟验证报告.md](6_模拟验证/模拟验证报告.md)。

## 🔗 提案假设 → 代码步骤 → 结果表

提案里的核心概念在代码里换了名字，对照如下：

| 提案说法 | 代码变量 | 含义 |
|---|---|---|
| Volume（current pool） | **C** | `log(1 + 同期在架同行业贷款数)` |
| Homogeneity（current pool） | **H** | 焦点贷款与同期池的平均余弦相似度（z 标准化） |
| Volume / Homogeneity（lagged pool） | **V / G** | 上架时点已满 35 天、未满 65 天的同行业贷款池，7 天半衰期加权 |
| Saturation = C × H | `current` 通道 | **RQ1 的检验对象** |
| Saturation = V × G | `recent` 通道 | **RQ2 的检验对象（wear-out），不是对照组／安慰剂** |

> **为什么是 35 天而不是 14 天**：训练期筹款时长 P95 = 826.891h = 34.45 天，向上取整为 35 天。
> 这保证滞后池里的贷款在焦点贷款上架那一刻已有 95% 的概率结束筹款，因此与焦点贷款的结果无关。
> 窗口定义见 [`frozen_spec.csv`](5_最终交付包/MA-Hackathon-Final-2026-09-04/outputs/frozen_spec.csv) 的 `Recent-history pool`
> 与 [05](3_分析步骤/05_构造池特征CHVG.ipynb) 的 `LAG_GAP_NS = 35*DAY_NS` / `LAG_END_NS = 65*DAY_NS`。

> **基准**：唯一有效的提案是 [2_提案/5 GUYS 提案.pdf](2_提案/5%20GUYS%20提案.pdf)
> 《WHEN EVERY STORY SOUNDS THE SAME》，结构为 **RQ1–RQ4**。
> [提案正文.md](2_提案/_未提交草稿/提案正文_BeyondCrowding_未提交.md) 和 [提案定稿.docx](2_提案/_未提交草稿/提案定稿_BeyondCrowding_未提交.docx)（《Beyond Crowding》，H1–H4）
