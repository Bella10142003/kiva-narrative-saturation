# Codex Proposal 起草规则

## 角色与权限

- Codex 是本项目的 proposal 主笔，负责整理要求、组织证据、设计提纲、起草正文并完成自检。
- `CONTEST_RULES.md` 是 Codex 与 Claude 共用的唯一竞赛标准。若其内容与竞赛原始材料不一致、缺失或尚未确认，停止相关定稿工作并标记为【待确认】。
- 未经用户明确要求，不修改、移动、重命名或删除任何竞赛原始资料；对原始资料的默认权限为只读。
- Codex 不得自行宣布 proposal 已获批准。只有 Claude 可以按照 `CLAUDE.md` 给出审批结论，最终提交仍须人工确认。

## 开始前的强制步骤

每次开始或继续起草前，必须：

1. 阅读项目中的全部竞赛要求、评分标准、官方模板和参考资料，不得只依赖摘要或既有草稿。
2. 阅读 `CONTEST_RULES.md`，确认比赛目标、受众、字数、格式、截止日期和评分标准是否完整。
3. 阅读 `proposal/requirements.md`、`proposal/evidence.md`、`proposal/assumptions.md` 和最近一次 `reviews/claude-review.md`。
4. 如发现资料缺失、相互冲突或含义不明确，将对应内容标记为【待确认】，不得自行补全。

## 起草流程

按以下顺序工作：

1. 在 `proposal/requirements.md` 中逐项登记竞赛要求及其原始出处。
2. 在 `proposal/evidence.md` 中登记拟使用的事实、数据和引用，并验证出处。
3. 在 `proposal/assumptions.md` 中记录所有假设和待确认事项。
4. 在 `proposal/outline.md` 中建立与评分标准对应的结构。
5. 在正文语言经人工确认后，起草或更新 `proposal/proposal.md`。
6. 在 `proposal/compliance-matrix.md` 中建立要求、评分项、正文位置和证据之间的对应关系。
7. 完成自检后，将草稿交由 Claude 独立审批。

## 事实与证据规则

- 不得虚构或推断成事实的数据、引用、政策、用户反馈、访谈内容、案例、合作关系或实验结果。
- 任何可核查陈述都必须能追溯到明确来源；无法核实的内容标记为【待确认】。
- 不得使用不存在的出处、占位引用或看似真实但未经验证的数字。
- 区分事实、推论、计划和假设，不得将计划效果写成已经实现的结果。

## 起草后强制自检

提交 Claude 审批前，必须完成并记录以下检查：

- 完整性：所有硬性要求、必答项和评分项均已覆盖。
- 逻辑：问题、目标、方案、实施、资源、风险和预期成果前后一致，无跳步或矛盾。
- 证据：关键主张均有可追溯证据；所有不确定信息均标记为【待确认】。
- 格式：字数、结构、文件格式、命名、引用和提交规则均符合 `CONTEST_RULES.md`。

存在未解决的关键问题时，不得将草稿描述为最终版或可提交版。
